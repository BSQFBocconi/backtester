# Architecture

How the backtester is put together: the event loop, the modules and what each folder is for.

## Event loop

```
DataHandler ──bar──▶ Strategy ──Order──▶ Broker (simulated) ──Fill──▶ Portfolio
     ▲                                                                   │
     └────────────── Engine loop (one bar at a time) ◀───────────────────┘
                                   │
                                   ▼
                              Metrics → Result
```

For each bar, the engine:

1. asks the **DataHandler** for the next bar;
2. sends the **Broker** any pending orders, which it fills at this bar's open price (with commission and slippage);
3. updates the **Portfolio** with the fills and marks positions to market;
4. calls the **Strategy**'s `on_bar`, which can place new orders.

When the data runs out, **Metrics** are computed from the equity curve and trade log and returned in a `Result`.

| Module | Responsibility |
|---|---|
| `data` | Load pre-gathered OHLCV files and serve bars one at a time, with access to past bars only. |
| `strategy` | `Strategy` base class. Members subclass it and implement `on_bar`. |
| `execution` | Simulated broker: turns orders into fills; commission and slippage models. |
| `portfolio` | Tracks cash, positions, the equity curve and the trade log. |
| `metrics` | Total/annualized return, volatility, Sharpe, Sortino, max drawdown, win rate. |
| `engine` | `Backtest` class: connects the components, runs the loop, returns the `Result`. |

### What each folder is for

**`src/bsqf_backtester/`** is the package itself, the code people get when they `import bsqf_backtester`.

- **`data/`** reads the CSV / Parquet files gathered in advance, checks they have the required columns, and gives the engine one bar at a time. It also lets the strategy look at past bars, never future ones.
  *Example:* `load_csv("data/AAPL.csv")` returns a clean table of prices.

- **`strategy/`** contains the `Strategy` base class. A member writing a strategy subclasses it and implements `on_bar`, which is called on every bar and decides whether to buy or sell. This folder holds the base class only, not members' strategies.
  *Example:* `class SmaCross(Strategy): def on_bar(self, ctx): ...`

- **`execution/`** simulates the broker. It takes the orders the strategy placed and decides **at what price and at what cost** they get filled (next bar's open, plus commission and slippage). It doesn't track your money.
  *Example:* "buy 100 shares" → "filled 100 shares at €150.02, fee €5".

- **`portfolio/`** handles the accounting. It applies each fill to your **cash** and **positions**, and at every bar records your **equity** (cash + value of positions) and the **trade log**. The metrics are computed from this record.
  *Example:* after buying 100 shares at €150 with €100,000, cash = €84,995, position = 100 shares.

- **`metrics/`** turns the equity curve and trade log into performance numbers: total and annualized return, volatility, Sharpe, Sortino, max drawdown, win rate.
  *Example:* `{"sharpe": 1.2, "max_drawdown": -0.18, ...}`

- **`engine/`** contains the `Backtest` class, which connects all the parts above and runs the loop bar by bar (data → fill orders → update portfolio → strategy). At the end it returns a `Result` with the metrics, equity curve and trades.
  *Example:* `Backtest(data, SmaCross(), cash=100_000).run()`

**Outside the package:**

- **`examples/`** has ready-to-run strategy scripts showing how to use the backtester. Start here if you're new.
- **`data/`** is where you put your local price files. Its contents are git-ignored, so data is never pushed to GitHub.
- **`tests/`** holds automated checks (pytest), ideally one test file per module. Run them with `uv run pytest`.
- **`pyproject.toml`** describes the project: its name, Python version and the libraries it needs.
- **`uv.lock`** is generated by uv and records the **exact** version of every library installed, including indirect ones. Never edit it by hand, but do commit it.
